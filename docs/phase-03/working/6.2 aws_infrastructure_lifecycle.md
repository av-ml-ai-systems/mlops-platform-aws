# AWS Infrastructure Lifecycle

## 1. Purpose

Define how AWS infrastructure for Phase 03 will be provisioned, operated, monitored, and cleaned up while controlling costs.

## 2. Infrastructure Management

- Use Terraform as the infrastructure-as-code tool.
- Reuse the existing AWS foundation from Phase 02 where appropriate.
- Extend existing Terraform configurations rather than duplicating resources.
- Keep infrastructure configuration separate from application and training code.
- Apply least-privilege IAM permissions.

## 3. Main AWS Components

The initial architecture may require:

- Amazon SageMaker Processing Jobs.
- Amazon SageMaker Training Jobs.
- SageMaker Pipelines.
- SageMaker Experiments.
- Amazon S3 for datasets, artifacts, and execution evidence.
- IAM for permissions.
- CloudWatch for logs and monitoring.

Only provision resources required by the current implementation stage.

## 4. Infrastructure Lifecycle

Follow this sequence:

1. Review Terraform configuration.
2. Initialize and validate Terraform.
3. Review the execution plan.
4. Provision required infrastructure.
5. Execute and validate the training workflow.
6. Preserve relevant artifacts, logs, metrics, and execution evidence.
7. Destroy temporary infrastructure when no longer required.
8. Verify resource cleanup.

## 5. Cost Management

- Prefer CPU-based instances initially.
- Avoid unnecessary persistent SageMaker resources.
- Use short execution periods and appropriate resource sizes.
- Monitor AWS costs and resource usage.
- Avoid leaving temporary resources running.

## 6. Artifact Preservation

Infrastructure cleanup must never destroy required project evidence.

Preserve relevant datasets, model artifacts, evaluation results, metadata, and logs before destroying temporary resources.

## 7. Implementation Principle

Infrastructure provisioning and cleanup must be explicit, repeatable, and independently verifiable.
